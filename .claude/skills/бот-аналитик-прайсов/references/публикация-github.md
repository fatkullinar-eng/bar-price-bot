# Публикация на GitHub

Открой этот справочник для запросов «опубликуй проект», «выложи
на GitHub», «добавь файлы в репозиторий».

## Чувствительное — НИКОГДА в паблик

| Что | Почему |
|---|---|
| `.env` | токен бота — кто его узнает, тот управляет ботом |
| `config.py` | реальные Telegram ID людей (в репозитории — только образец `config_example.py`) |
| `прайсы/`, `история/`, `отчёты/` | коммерческие цены поставщиков |
| `bot-log.txt` | имена, ID, цены, события |
| `__pycache__/`, `tmp/`, `*.bak` | служебные файлы и одноразовые скрипты |
| адрес сервера, ssh-ключи, пути с именем пользователя | приглашение взломщикам |

## Чек-лист перед каждым push (порядок обязателен)

1. Убедиться, что `.gitignore` закрывает всё из таблицы выше.
2. **Проверка ДО коммита (строго):**
   - `git status --porcelain` и `git ls-files --cached` — просмотреть
     глазами ВСЕ файлы, которые попадут в паблик-набор;
   - убедиться: НЕТ `.env`, НЕТ `config.py`, НЕТ папок `прайсы/`,
     `история/`, `отчёты/`, НЕТ `bot-log.txt`, НЕТ `__pycache__/`;
   - поиском по готовящимся файлам проверить, что нет адреса
     сервера, `BOT_TOKEN=`, имён пользователей и других внутренних
     деталей.
3. **Коммит** — только после чистой проверки.
4. **Push и сама публикация** — только после явного разрешения
   владельца, предварительно перечислив ему, что именно уйдёт наружу.

## Проверка после публикации

1. Открыть репозиторий в браузере (github.com → имя аккаунта →
   имя репозитория) и вручную просмотреть список всех файлов.
2. Убедиться: `.env` и папки данных отсутствуют.
3. Пройти по паре файлов глазами — нет ли внутри адреса сервера
   или других внутренних деталей.

## Напоминание

Публичный репозиторий видит весь мир: если хоть один файл с ценами
или токеном проскочит — коммерческие данные станут доступны всем.
Приватный репозиторий — безопасный первый шаг; публичность можно
включить потом. Удалённое с GitHub не стирается бесследно: то, что
однажды опубликовано, может остаться в чужих копиях навсегда.
