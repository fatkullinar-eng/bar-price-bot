# Диагностика и перезапуск бота

Открой этот справочник для запросов «бот молчит», «бот не отвечает»,
«проверь бота», «перезапусти». Действуй строго по шагам,
не перескакивая.

## Подключение к серверу (основа)

Подключение по ssh — подставьте свои значения (адрес сервера
и пользователя выдаёт хостинг VPS):

```
ssh <пользователь>@<адрес-сервера>
```

В примерах ниже путь к проекту на сервере — `/opt/bar-price-bot`.
Если у вас путь другой (например, `/root/bar-price-bot`) —
подставляйте свой.

Управление службой (внутри ssh-команды, служба настраивается один раз
по любой инструкции «systemd + Python»):

```
ssh <пользователь>@<адрес-сервера> "systemctl status bar-price-bot --no-pager"
```

- `systemctl status bar-price-bot` — жив ли, сколько было рестартов;
- `systemctl restart bar-price-bot` — перезапуск;
- `systemctl stop bar-price-bot` / `systemctl start bar-price-bot` —
  остановка / запуск.

Журналы:

- дневник бота: `ssh ... "tail -n 50 /opt/bar-price-bot/bot-log.txt"`;
- журнал службы: `ssh ... "journalctl -u bar-price-bot -n 50 --no-pager"`.

## Протокол «бот молчит» (жёсткая последовательность)

**Шаг 1. Проверить статус службы.**
`systemctl status bar-price-bot --no-pager`. Если служба настроена
с Restart=always — при падении она сама перезапускается. Если бот
«active», но молчит — шаг 2. Если счётчик рестартов быстро растёт —
бот циклически падает, причина в дневнике.

**Шаг 2. Прочитать хвост дневника.**
`tail -n 50 /opt/bar-price-bot/bot-log.txt`. Искать: `Traceback`,
`409` / `Conflict`, кракозябры вместо русских букв.

**Шаг 3. Разбор по диагнозу.**

- **409 / Conflict** — где-то работает второй экземпляр бота (двое
  ботов делят один токен — например, запустили и на сервере, и на
  компьютере). Найти и остановить один из двух.
- **Traceback** — ошибка в коде, почти всегда после свежего деплоя.
  Прочитать последнюю ошибку, соотнести с последним изменением,
  починить ЛОКАЛЬНО, протестировать в песочнице, задеплоить заново
  по `деплой-на-сервер.md`.
- **Кракозябры вместо русских букв в дневнике** — симптом: запуск
  без переменной `PYTHONUTF8=1`. Добавить её в Environment службы
  systemd (или в запуск bat/скрипта), перезапустить — дневник станет
  читаемым.
- **Зависание после сна компьютера** — в локальном режиме бывает:
  процесс жив, но сообщения не приходят, в журнале тишина. Лечение —
  перезапуск процесса.
- **Молчит, а дневник чистый** — проверить, что `.env` на сервере
  содержит строку токена (`ssh ... "grep -c '^BOT_TOKEN=.'
  /opt/bar-price-bot/.env"` — команда печатает только число строк,
  содержимое не выводится), проверить сеть сервера и доступность
  Telegram API.

**Шаг 4. После лечения.**

1. `systemctl restart bar-price-bot`.
2. `systemctl status bar-price-bot --no-pager` — убедиться: active.
3. `tail -n 20 /opt/bar-price-bot/bot-log.txt` — старт чистый,
   без Traceback.
4. Попросить владельца отправить боту `/start` в Telegram
   и подтвердить, что ответ пришёл.
5. Отчитаться владельцу простыми словами: что было, что сделал,
   что теперь.
